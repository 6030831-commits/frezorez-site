## 🔴 Дыры, вскрытые прожаркой (закрыть ДО «зелёного света»)

1. **Всё, кроме drift-контроля, гейтится на одном OAuth-токене Яндекса.** Метрика и Вебмастер
   без токена не читаются → агенты 2 и 3 не стартуют. **Действие владельца:** выпустить токен
   по инструкции в `.env.example`, вставить в `.env`. Это блокер №1.
2. **Пост-деплойные шаги — это НЕ агенты, а ручной чек-лист.** Их пропуск = потеря позиций
   мимо всякой автоматизации (см. чек-лист ниже).
3. **Baseline дрейфа должен сниматься с ФИНАЛЬНОГО задеплоенного билда.** Если владелец
   пересоберёт/поправит перед заливкой — старый baseline даст ложные тревоги. → Пере-снять
   `node seo/make-baseline.mjs` на том билде, что реально уходит в прод.
4. **Контент-агент НЕ должен публиковать сам.** Риск: выдуманные факты (цена, ТТХ лазера) и
   сырой текст на живом сайте. → Работает через git-ветку/PR, владелец ревьюит, автопуша нет.
5. **Runner для крона.** Git-remote есть (github.com/6030831-commits/frezorez-site) → облачные
   рутины `/schedule` жизнеспособны. Секреты (токены) кладутся в env рутины, не в репозиторий.

## Агенты

### Агент 1 — Drift-контроль (готов, стартует сразу)
- **Что:** `node seo/drift-check.mjs https://frezorez.ru`.
- **Ловит:** URL упал в non-200, появился noindex, сломался/пропал canonical, пропала JSON-LD,
  изменились title/description против эталона.
- **Каденс:** ежедневно первые 14 дней после переезда (критическое окно индексации), затем еженедельно.
- **Порог:** любой CRITICAL (non-200 / noindex / canonical) → чинить немедленно.
- **Зависимости:** нет. Работает и локально, и облачной рутиной.

### Агент 2 — Индексация и позиции (Яндекс Вебмастер API) — гейт: токен
- **Что:** новые/выпавшие из индекса страницы, запросы, показы, средняя позиция по KEEP-URL.
- **Каденс:** ежедневно первую неделю (быстро поймать деиндексацию KEEP-URL), затем еженедельно.
- **Порог:** выпал KEEP-URL или позиция по ядру просела >5 → разбор.
- **Зависимости:** OAuth-токен с доступом к Вебмастеру; host_id домена.

### Агент 3 — Трафик и поведенческие (Яндекс Метрика API) — гейт: токен
- **Что:** визиты, источники, поведенческие (отказы, глубина) по разделам; сравнение неделя-к-неделе.
- **Каденс:** еженедельно.
- **Порог:** падение органического трафика >20% WoW без сезонной причины → разбор.
- **Зависимости:** OAuth-токен (тот же), `scripts/metrica-check.mjs` расширить до разбивки по страницам.

### Агент 4 — Контент (обогащение + рост) — ревью-гейт
- **Что:** дотягивает тонкие страницы ядра (<250 слов) и создаёт новые по `semantics.md`,
  через скиллы copywriting + seo + content-strategy. Правило проекта: **не выдумывать данные бизнеса**
  (цена, ТТХ лазера — только заглушки `[НУЖНА ЦИФРА]`).
- **Как:** пишет в git-ветку `content/<дата>` → PR → владелец ревьюит и мёржит. **Автопуша в прод нет.**
- **Каденс:** еженедельно, 1–3 страницы за проход.
- **Зависимости:** `semantics.md` (есть, 46 строк), git-remote (есть).

### Агент 5 — Мониторинг SERP/конкурентов (firecrawl monitor) — готов
- **Что:** следит за изменениями на страницах конкурентов и за собственной индексацией
  (напр. кэш выдачи по ядру), алерт на вебхук/почту.
- **Каденс:** встроенный (min 5 мин; для SEO хватит ежедневного).
- **Пример:** `firecrawl monitor create --name "Конкуренты фрезеровка" --schedule "daily" --goal "Alert when competitor pricing or service pages change." --scrape-urls <url1>,<url2>`
- **Зависимости:** нет (firecrawl авторизован).

## Оркестрация и запуск

- **Механизм:** облачные рутины через скилл `/schedule` (репозиторий на GitHub — доступен облаку).
  Токены — в env рутины (не в git). Альтернатива без облака: `/loop` локально, когда владелец
  держит Claude Code открытым.
- **marketing-loops** — как методология каденса/связки скиллов внутри контент- и мониторинг-циклов.
- **Приоритет запуска завтра:** Агент 1 (drift) + чек-лист переезда → затем токен → Агенты 2, 3 →
  Агент 5 (monitor) → Агент 4 (контент, ревью-гейт).
